# Идеи

Мысли «а что если…», которые появились по ходу работы. Это не план: идея попадает в `plan.md` только после обсуждения с командой.
Формат: короткое название — суть, зачем, примерная цена. Новые — внизу.

- **Извлекать из записей экрана не только инструкцию.** Эксперт во время записи часто проговаривает правила и исключения («тут всегда проверяю дату»). Тот же `SourceDocument` из шагов записи можно прогнать через общее извлечение и получить карточки `rule` / `pitfall`. Цена: небольшая, код извлечения общий.
- **Таблица `llm_calls` с метаданными вызовов** (промпт, версия, модель, задержка, токены, успех/ошибка JSON) без текстов. Даёт панель «качество ИИ» для жюри и отладку медленных ходов интервью. Цена: таблица + обёртка в провайдере.
- **Проверка в CI, что `frontend/src/api/schema.d.ts` актуален** (сгенерировать и сравнить с закоммиченным). Ловит забытый `make gen-api`. Цена: один шаг CI.
- **Один вызов LLM на ход интервью вместо двух**, если не уложимся в 8 с: `analyze_turn` возвращает и анализ, и черновик вопроса, а планировщик только выбирает цель. Минус — хуже контроль. Решать по замерам.
- **Срок актуальности карточки.** Поле «пересмотреть через N месяцев» и напоминание эксперту/руководителю: знания устаревают (новый регламент, другая система). Хороший аргумент для пилота после ухода эксперта.
- **Режим «проверь преемника».** Ассистент задаёт преемнику вопросы по базе (обратный экзамен) и показывает руководителю, какие процессы он ещё не усвоил. Метрика готовности преемника для финмодели.
- **`make demo` одной командой** = `make up` + `make seed-demo` + открыть браузер. Удобно для жюри и новых участников команды. Цена: три строки в Makefile.
- **Ограничение частоты попыток входа** (например, 10 попыток в минуту на email/IP) с записью в аудит. Для пилота у заказчика это стандартный вопрос безопасников. Цена: небольшая таблица или счётчик в памяти.
- **Строгий запуск вне демо-режима**: если `DEMO_MODE=false`, а `JWT_SECRET` остался по умолчанию, — не стартовать (сейчас только предупреждение в логе). Цена: одна проверка.
- **Стриминг вопроса интервьюера.** Вопрос короткий, но на локальной модели ход может занять 5–8 с; если показывать вопрос по мере генерации, ожидание ощущается вдвое короче. Провайдер `stream()` уже есть. Цена: SSE на одном эндпоинте.
- **Повторное извлечение с новой версией промпта.** Кнопка «Пересобрать черновики» для сессии: удобно сравнивать версии `extract_cards.md` на одном и том же интервью. Цена: снять `extracted_at` + дедупликация уже защищает от дублей.
- **«Откуда эта карточка» в интервью.** В чате интервью подсвечивать реплики, из которых родились карточки. Эксперт видит, какие ответы оказались полезными, и лучше отвечает дальше.
- **События для демо-панели.** Сид может записывать в `events` правдоподобную историю (ходы интервью, подтверждения), чтобы панель руководителя (M4) не была пустой на демо.
- **Примеры вопросов от модели.** Сейчас на пустом экране ассистента — заголовки карточек (как в ТЗ). При подтверждении карточки LLM могла бы сформулировать 1–2 естественных вопроса к ней; ими же можно пополнять eval-набор. Цена: поле в карточке + один вызов LLM.
- **Реранкер для топ-чанков** (например, bge-reranker через llama.cpp `--rerank`), если eval покажет, что нужная карточка часто есть в топ-20, но не в топ-5. Цена: ещё один сервер модели.
- **Двумерный перебор порогов в eval** (косинус × покрытие словами) вместо двух одномерных — если пороги окажутся зависимыми. Цена: таблица в отчёте.
- **Структурирование ответа эксперта на пробел через LLM** (тип, суть, «когда применять») вместо карточки «как есть». Эксперт всё равно проверяет черновик. Цена: промпт + один вызов.
- **Кэш ответов на одинаковые вопросы** в рамках передачи до изменения базы. На демо и пилоте вопросы повторяются; экономит 5–15 с локальной модели.
- **`make reindex`** — пересобрать индекс ассистента всех подтверждённых карточек (после смены модели эмбеддингов на реальных данных). Сейчас на демо это делает `make seed-demo`. Цена: маленький скрипт поверх `index_card`.
- **Ручное размытие на скриншоте** при проверке карточки (Should из ТЗ п. 7.6.1): эксперт рисует прямоугольник, кадр пересохраняется. Закрывает то, что автоматика не находит (одна фамилия в поле поиска). Цена: редактор поверх картинки + эндпоинт.
- **Размытие и в видео**, а не только на скриншотах: сейчас преемник видит видео как есть. Можно размывать боксы с ПДн по кадрам с шагом 1 с (ffmpeg + OCR) — дорого, но закрывает главный риск записей. Цена: время обработки ×10.
- **Предупреждение до записи**, если на экране видны ПДн: проверить первый кадр трансляции OCR'ом прямо в браузере перед стартом. Цена: Tesseract.js или запрос к backend.
- **Шаги без модели**: если LLM недоступна, разбивать запись на шаги по паузам в речи (D-049 для записей). Демо без модели получило бы инструкцию из любой записи. Цена: эвристика на таймкодах слов.
- **Процесс у пробела.** Сейчас в карте рисков пробелы считаются по передаче, а не по процессу (D-070). Если брать процесс у самой близкой найденной карточки (данные поиска уже лежат в `qa_logs.retrieval`), колонка станет точнее. Цена: поле в `gaps` + миграция.
- **«Мои данные» для преемника.** Удаление своих вопросов ассистенту (`qa_logs`) по запросу — тот же реестр `DataEraser`. Цена: один eraser в `assistant` и страница.
- **Покрытие с учётом числа карточек.** Одна карточка-инструкция закрывает сразу 4 аспекта, поэтому покрытие быстро доходит до 100 %. Можно требовать по карточке на аспект или учитывать раскрытость в интервью. Цена: правка чистой функции и согласование формулы.
