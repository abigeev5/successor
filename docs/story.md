### M0. Каркас — готов
Критерий этапа выполнен: `make up` поднимает db, backend, worker и frontend; вход под всеми четырьмя демо-учётками проверен в браузере (Playwright) на собранном фронтенде за nginx; `make test` и `make lint` зелёные; CI на GitHub Actions — lint, тесты на fake-провайдерах с PostgreSQL, сборка фронтенда и образов ([первый прогон — зелёный](https://github.com/abigeev5/successor/actions/runs/39014701366)).

Что сделано:
- **Backend** (`backend/`, Python 3.12, uv): `core` — настройки, БД (async SQLAlchemy), ошибки в формате `{"detail", "code"}` на русском, argon2 + JWT в httpOnly cookie, шина событий, очередь задач на таблице `jobs` (`SKIP LOCKED`, повторы с экспоненциальной задержкой, `dedup_key`, возврат зависших задач), реестр промптов с версиями, HTTP-клиент с проверкой `OFFLINE_MODE`, `/api/health`, `/api/meta`.
- **Провайдеры**: интерфейсы LLM, эмбеддингов, ASR, OCR, VLM и fake-реализации; структурированный JSON-вывод с двумя повторами и подсказкой из `prompts/json_retry.md`.
- **Модули**: `identity` (вход, выход, `me`, пользователи для админа), `org` (подразделения, процессы, знающие; API подразделений для админа), `handovers` (передачи, участники, процессы; единая проверка прав — чистая политика `domain/policy.py` + `access.py`), `audit` (журнал: вход, неудачный вход, изменения пользователей и подразделений).
- **Миграции**: начальная миграция Alembic + расширение `vector`; хуки autogenerate против дублей CHECK (урок L-001).
- **Worker**: `python -m app.worker`, корректная остановка по сигналу.
- **Сид**: подразделение «Учебный отдел (демо)» и 4 демо-пользователя, идемпотентно.
- **Тесты**: 89 на backend (юнит: безопасность, политика доступа, события, очередь, fake-провайдеры, промпты, офлайн-режим, формат ошибок; интеграционные на PostgreSQL: вход и аудит, админка, доступ к передаче, очередь задач, сид, соответствие миграций моделям) и 3 smoke-теста фронтенда.
- **Frontend** (`frontend/`, React 18 + Vite + TS + Tailwind 4): вход с подсказкой демо-учёток, редирект по роли, layout с разделами по ролям, баннер «Демо-режим», заглушки разделов с понятными пустыми состояниями, типизированный клиент API из OpenAPI (`make gen-api`); адаптивная шапка.
- **Инфраструктура**: `docker-compose.yml` (db, backend, worker, frontend на nginx), `Makefile` (`up`, `down`, `test`, `lint`, `seed-demo`, `eval`, `gen-api`, `dev-*`), `.env.example`, GitHub Actions, README.

Ошибки этапа — в `lessons.md` (L-001…L-004).

### M1. Интервьюер и карточки — код готов
Команда выбрала faster-whisper `small` и локальный llama.cpp (D-031, D-032); модели не скачивались, всё проверено на fake-провайдерах и подменённом HTTP. Осталась проверка на реальной модели и видео (см. `plan.md`).

Что сделано:
- **Провайдеры**: LLM через OpenAI-совместимый API (llama-server, vLLM, Ollama): `response_format: json_schema`, вырезание `<think>`, стриминг, понятные ошибки; эмбеддинги через `llama-server --embeddings`; faster-whisper с ленивой загрузкой модели. В приложении без модели интервьюер задаёт заготовленные вопросы (D-045).
- **Передачи дел и процессы**: создание и правка передач (эксперт, преемник, процессы, срок), «кто знает процесс» (эксперт — owner, преемник — learning, без понижения уровня), CRUD процессов, справочник сотрудников подразделения.
- **Согласие**: текст `consent_v1.md` с версией и хешем, принять / отозвать; без согласия интервью и голос — 403 с понятным текстом.
- **Интервьюер**: аспекты и порядок зондов из ТЗ, чистый планировщик (`intro → map → walkthrough → deepen → wrapup`, не больше двух зондов подряд по одному аспекту, переход при покрытии ≥ 70 %), анализ хода и генерация вопроса через LLM с заготовленными вопросами при сбое, карта обязанностей (кандидаты в процессы → подтверждение), пауза / следующий процесс / завершение, активное время, покрытие в `process_aspects`.
- **Голос**: запись в браузере до 2 минут → загрузка → распознавание → правка → отправка; проверка формата по сигнатуре, хранение в `assets`.
- **Карточки**: общий `SourceDocument`, окна с перекрытием, извлечение через LLM, проверка цитат (сохраняется найденный фрагмент реплики, минимум 3 слова), привязка к процессу с учётом падежей, дедупликация по эмбеддингам, черновики; проверка экспертом: подтвердить (с правками — с ревизией), отклонить, объединить, создать вручную; преемник видит только подтверждённые карточки и только цитаты.
- **События**: таблица `events` для продуктовых метрик (`interview_turn`, `card_generated`, `card_dropped_no_evidence`, `card_approved` …).
- **Демо-данные**: 4 процесса, 5 сотрудников, завершённое интервью (38 реплик), покрытие, 25 подтверждённых и 5 черновых карточек; сид проверяет каждую цитату.
- **Фронтенд**: список и создание передач, обзор передачи с покрытием, согласие, интервью (чат, покрытие, карта обязанностей, голос), проверка карточек (очередь по процессам, редактор с предпросмотром, источники с подсветкой цитаты, A / R / J / K, время проверки).
- **Тесты**: backend 168 (планировщик, анализ хода, цитаты, окна, дедупликация, сопоставление названий, провайдеры; интеграционные — полный цикл интервью → извлечение, проверка карточек и права, согласие, голос, передачи, сид), frontend 6. Сценарии проверены в браузере.

Находки по ходу:
- Тест показал, что LLM пишет названия процессов в других падежах («отчет по контингенту»), и нечёткое сравнение их не находило. Сопоставление переделано на основы слов с защитой от неоднозначности.
- Ошибки этапа — `lessons.md` L-005, L-006.
