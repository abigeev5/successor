# План работ

Поэтапный план. Правила ведения:
- выполненный пункт **удаляется** отсюда, а запись о нём попадает в [`story.md`](story.md);
- этап закрыт, когда выполнены все его пункты и критерий «Готово, когда»; тогда этап удаляется целиком;
- новые пункты добавляются только по согласованию с командой; мысли «на будущее» — в [`ideas.md`](ideas.md).

Сроки — из ТЗ (раздел 14). При отставании режем Should, а не Must.

---

## M1. Интервьюер и карточки (20–30 октября) — для спринта 1

Код этапа готов (см. `story.md`). Остались проверки, для которых нужна реальная модель.

**Готово, когда:** с реальной LLM эксперт проходит интервью из ≥ 10 ходов, вопросы осмысленные и не повторяются; после завершения появляются черновики, у каждого есть хотя бы одна цитата, которая реально есть в интервью (тест есть); эксперт может подтвердить / поправить / отклонить; записано видео-демо этой части.

1. Команда: выбрать и скачать GGUF-модели (LLM 7–14B и bge-m3), запустить `llama-server` по README.
2. Прогнать интервью из ≥ 10 ходов на реальной модели; по результатам поправить промпты `analyze_turn.md`, `interviewer_system.md`, `extract_cards.md` (новые версии в front matter) и замерить время хода (цель < 8 с).
3. Проверить извлечение на реальной модели: доля карточек, отброшенных из-за цитат; при большой доле — уточнить промпт.
4. Записать видео-демо интервью и проверки карточек.

## M2. Ассистент и качество (2–14 ноября)

**Готово, когда:** `make eval` выдаёт отчёт; на демо-наборе корректных отказов ≥ 80% и правильных ответов ≥ 70%; клик по ссылке открывает карточку и её первоисточник.

1. Провайдер эмбеддингов (`openai_compatible` / `sentence_transformers`, bge-m3).
2. `search`: чанки, индексация по `CardApproved`, удаление по `CardRejected` / `CardArchived`, гибридный поиск + RRF.
3. `assistant`: решение об отказе, `answer.md`, разбиение на утверждения, `verify_claims`, сборка ответа, `qa_logs`, обратная связь.
4. `gaps`: создание по `AnswerRefused` и вручную, ответ эксперта → черновик (`gap_answer`), закрытие после подтверждения, переназначение, уведомление преемнику.
5. Frontend: ассистент (чипы источников, боковая панель с первоисточником), база знаний, пробелы.
6. Eval: `demo_qa.jsonl` (50–60 вопросов, ≥ 15 неотвечаемых, 5–10 с подвохом), `run_eval.py` (`--provider fake|real`), подбор `RAG_MIN_SIMILARITY`, отчёт в `eval/reports/`, шаг в CI.
7. Тесты: RRF, порог отказа, разбиение / сборка утверждений; интеграционный «вопрос → ответ со ссылкой», «вопрос без ответа → отказ → пробел».

## M3. Записи экрана и ПДн (10–22 ноября)

**Готово, когда:** 5-минутная запись в mock-portal превращается в инструкцию из 5–12 шагов со скриншотами; тестовый кадр с телефоном, email и ФИО размывается (юнит-тест на фикстуре).

1. `ffmpeg` в образ backend/worker (D-029); `recordings`: загрузка (MIME по содержимому, лимит размера), `process_recording` (ffmpeg, ASR, `segment_recording`, `fix_steps`, кадры), черновик `procedure`.
2. ПДн: OCR-провайдер, детекторы (регулярки, Луна, natasha), размытие (OpenCV).
3. `/assets/{id}` со стримингом и Range.
4. Frontend: захват экрана / загрузка файла, прогресс, страница записи (видео + шаги), видео-источник в проверке и ассистенте.
5. `demo/mock-portal`, демо-запись с транскриптом для `FakeASR`.
6. Тесты: детекторы ПДн, размытие на фикстуре, валидация шагов.

## M4. Панель руководителя, приватность, аудит (18–27 ноября)

**Готово, когда:** удаление записи экспертом убирает файлы, шаги и архивирует карточки без других источников (интеграционный тест); риск процесса меняется после подтверждения карточек; приложение работает с `OFFLINE_MODE=true` и локальной моделью.

1. `analytics`: прогресс, покрытие подтверждёнными карточками, риск (пороги в конфиге), метрики + CSV, матрица «процессы × аспекты» (Should).
2. `privacy`: каскад удаления через `DataEraser`, отзыв согласия, чистка медиа по сроку.
3. `audit`: события из ТЗ п. 12, `GET /audit`.
4. Профиль `local-llm` в docker-compose (vLLM / Ollama, D-027) и проверка `OFFLINE_MODE=true`.
5. Frontend: панель руководителя, приватность.
6. `docs/privacy.md`.
7. Тесты: формула риска, каскад удаления.
