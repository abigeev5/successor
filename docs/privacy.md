# Защита данных

Документ составлен по коду (ТЗ, п. 12) и описывает поведение на момент M4: какие данные собираются, где хранятся, кто их видит и как удаляются. Нужен для слайда «Защита данных» и для разговора с безопасниками заказчика. Если код изменится, документ нужно обновить.

## Где всё хранится

- **Всё внутри контура организации.** PostgreSQL (данные, индекс ассистента, очередь задач) и файлы (`STORAGE_DIR`, volume `appdata`) находятся на сервере организации. Модели (LLM, эмбеддинги, распознавание речи, OCR) тоже работают локально: llama.cpp на хосте или в профиле `local-llm`, faster-whisper и Tesseract — в образе backend.
- **`OFFLINE_MODE=true`** запрещает обращения к нелокальным адресам. Разрешены только `localhost`, частные диапазоны IP и имена сервисов docker compose. Адреса проверяются при старте (приложение не запустится с внешним `LLM_BASE_URL`) и при каждом запросе HTTP-клиента провайдеров. GigaChat в этом режиме недоступен.
- **У файлов нет публичных ссылок.** Их отдаёт только `GET /api/assets/{id}`, и при каждом запросе проверяется право на передачу дел. Путь к файлу формирует сервер, а не клиент, поэтому выйти за пределы хранилища (path traversal) нельзя. Тип файла проверяется по содержимому, размер загрузки ограничен (голос — 2 минуты, видео — `RECORDING_MAX_MB`).
- **Логи приложения не содержат текстов** вопросов, ответов и расшифровок: только id и числа. Таблица продуктовых метрик `events` тоже хранит только id и числа.

## Какие данные собираются

| Данные | Откуда | Таблицы / файлы |
|---|---|---|
| ФИО, email, роль, подразделение, хеш пароля (argon2) | администратор | `users` |
| Согласие: версия и хеш текста, время, IP | эксперт | `consents` |
| Реплики интервью (текст), голосовые ответы | эксперт | `interview_sessions`, `interview_messages`, файлы audio |
| Записи экрана с голосом, расшифровка, шаги, скриншоты | эксперт | `recordings`, `transcript_segments`, `recording_steps`, файлы video и image |
| Ответы эксперта на вопросы преемника | эксперт | `gaps.answer_text`, файлы audio (голос) |
| Карточки знаний и цитаты-источники | извлечение из реплик, записей и ответов + проверка экспертом | `knowledge_cards`, `card_sources`, `card_revisions`, индекс `card_chunks` |
| Вопросы преемника и ответы ассистента | преемник | `qa_logs`, `gaps` |
| Журнал аудита | система | `audit_log` |
| Продуктовые метрики (без текстов) | система | `events` |

**Персональные данные на скриншотах** размываются автоматически до сохранения: телефоны, email, СНИЛС, ИНН, паспорта, номера карт (с проверкой Луна) и ФИО. Оригинал кадра не сохраняется. Если OCR не сработал, скриншот не сохраняется вовсе (D-058). **Видео записи не размывается**: его видят эксперт, руководитель и преемник этой передачи дел. Поэтому перед записью интерфейс напоминает закрыть личные вкладки.

## Кто что видит

Доступ проверяется в одном месте (`handovers/access.py`) по роли пользователя в конкретной передаче дел.

| Что | Эксперт | Руководитель | Преемник | Админ |
|---|---|---|---|---|
| Реплики интервью и голос | ✓ свои | — | — | ✓ |
| Карточки: черновики, отклонённые, архив | ✓ | ✓ | — | ✓ |
| Подтверждённые карточки | ✓ | ✓ | ✓ | ✓ |
| Источник карточки: полный текст реплики / шага | ✓ | ✓ | только цитата | ✓ |
| Записи экрана: страница с шагами | ✓ | ✓ | — | ✓ |
| Видео записей и скриншоты (файлы) | ✓ | ✓ | ✓ своей передачи (открываются из источников карточек) | ✓ |
| Файлы голосовых ответов | ✓ | ✓ (по id файла; в интерфейсе ссылок нет) | — | ✓ |
| История вопросов ассистенту | — | свои | свои | свои |
| Вопросы без ответа (пробелы) | ✓ | ✓ | свои | ✓ |
| Панель руководителя, метрики, CSV | — | своё подразделение | — | ✓ (через API) |
| Журнал аудита | — | действия сотрудников своего подразделения | — | всё |

Руководитель видит передачи, где он назначен руководителем, и все передачи своего подразделения.

> **Расхождение с текстом согласия.** Черновик согласия (`consent_v1.md`) говорит, что руководитель видит «ход работы и подтверждённые карточки». По коду руководитель видит ещё черновики карточек с полным текстом реплик-источников и записи экрана. Нужно решить, что менять: права доступа или текст согласия.

## Журнал аудита

Записываются: вход и неудачный вход; создание и изменение пользователей, подразделений, процессов и передач дел; принятие и отзыв согласия; создание, правка, подтверждение, отклонение и объединение карточек; загрузка, **просмотр** и удаление записи экрана; ответы на пробелы, их закрытие и переназначение; **удаление данных сотрудника**; удаление медиа по сроку хранения.

Просмотр записи пишется, когда видео отдаётся через `/api/assets`, — не чаще раза в 30 минут на пользователя и файл: плеер запрашивает видео кусками много раз подряд. Журнал не содержит текстов, только id и короткие метаданные (например, сколько файлов удалено). Посмотреть его можно в разделе «Журнал» (`GET /api/audit`).

## Как данные удаляются

### Эксперт удаляет запись экрана

«Мои данные» → «Удалить запись» (`DELETE /api/recordings/{id}`). Удалить запись может её автор или администратор, но не во время обработки.

1. Файлы видео и скриншотов удаляются с диска сразу. Строки `assets` остаются с отметкой `deleted_at`, потому что на них ссылаются другие таблицы.
2. Расшифровка (`transcript_segments`) и шаги (`recording_steps`) удаляются из БД.
3. У карточек исчезают ссылки на удалённые шаги. Карточка, у которой не осталось ни одного источника, уходит в архив (`archived_reason = source_deleted`) и удаляется из индекса ассистента. Карточка, у которой остались другие источники, продолжает работать.
4. В журнал пишется `recording.deleted`.

### Эксперт удаляет все свои данные по передаче

«Мои данные» → «Удалить мои данные» (`DELETE /api/privacy/my-data?handover_id=…`). Каждый модуль, который хранит данные сотрудника, регистрирует свой `DataEraser`:

- **интервью** — удаляются все сессии эксперта вместе с репликами, а голосовые файлы удаляются с диска;
- **записи экрана** — всё, что перечислено в предыдущем разделе, для всех записей эксперта;
- **пробелы** — текст ответов эксперта стирается; вопрос, на который уже ответили, снова становится открытым;
- **остальные файлы эксперта** в этой передаче (например, голосовой ответ, который распознали, но не отправили) — удаляются с диска.

Затем карточки, у которых не осталось источников, уходят в архив и пропадают из ассистента. В журнал пишется `data.erased` с количеством удалённого.

Что **остаётся**: запись о согласии (факт, что и когда было принято или отозвано), журнал аудита и метрики (без текстов), архивные карточки, которые эксперт сам подтвердил, а также покрытие аспектов процессов (это не персональные данные). Удаление нельзя отменить. Страница «Мои данные» показывает, что сейчас хранится.

### Отзыв согласия

«Мои данные» → «Отозвать согласие» (`POST /api/consents/{id}/revoke`). После отзыва интервью, голосовые ответы и записи экрана недоступны (403 с объяснением). Уже собранные данные остаются, пока эксперт не удалит их на той же странице.

### Срок хранения сырых медиа

Worker раз в `RETENTION_CHECK_INTERVAL_S` (по умолчанию — час) ставит задачу `purge_raw_media`. Она удаляет аудио и видео старше `RETENTION_DAYS_RAW_MEDIA` дней (по умолчанию 180). Скриншоты (уже размытые), шаги, расшифровки и карточки остаются. На странице записи вместо плеера появляется пометка «Видео удалено по сроку хранения», а источники карточек больше не предлагают видео. В журнал пишется `media.purged`.
