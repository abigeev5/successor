Ты извлекаешь из интервью карточки знаний для преемника сотрудника. Сотрудник уходит, а преемник должен суметь сделать его работу по этим карточкам.

Процессы, о которых идёт речь:
{% for p in processes %}- {{ p }}
{% else %}- (список процессов пока пуст)
{% endfor %}
Фрагмент интервью. Реплики сотрудника пронумерованы в квадратных скобках; перед некоторыми есть вопрос интервьюера — он только для контекста.

{% for f in fragments %}{% if f.context %}Интервьюер: {{ f.context }}
{% endif %}[{{ f.n }}] Сотрудник: {{ f.text }}

{% endfor %}
Создай карточки только о том, что сотрудник реально сказал. Ничего не добавляй от себя, не обобщай и не придумывай шаги, сроки, имена.

Типы карточек:
- procedure — инструкция: последовательность шагов;
- rule — правило или признак: «если…, то…», «понимаю, что готово, когда…»;
- exception — исключение: когда обычный порядок не работает и что делать;
- pitfall — типичная ошибка новичка и как её избежать;
- contact — к кому (к какой роли) обращаться и с чем;
- deadline — сроки, периоды, календарь;
- term — термин или местный жаргон и что он значит.

Для каждой карточки:
- type — один из типов выше;
- process_name — название процесса из списка, к которому она относится, или null;
- title — короткое название, понятное новичку (до 10 слов);
- summary — 1–2 предложения сути;
- body_md — содержание в Markdown; для procedure — нумерованный список шагов;
- applies_when — когда это применимо, или null;
- quotes — 1–3 ДОСЛОВНЫЕ цитаты из реплик сотрудника, подтверждающие карточку: fragment — номер реплики, text — точный фрагмент её текста (не меньше 3 слов, без пересказа).

Одна мысль — одна карточка. Не дублируй карточки. Если полезных для преемника знаний во фрагменте нет, верни пустой список.

Верни JSON: {"cards": [...]}
