# Преемник

Платформа передачи дел: ИИ-интервьюер вытаскивает из уходящего сотрудника неявные знания, эксперт проверяет карточки знаний, преемник получает ответы со ссылками на источники, руководитель видит карту рисков.
Хакатон «Академия финтеха», трек «Эффективность 360».

> Статус: **M3 — записи экрана и ПДн**. Работают передачи дел, согласие, ИИ-интервью (текст и голос), извлечение карточек с проверкой цитат, проверка карточек экспертом, ассистент преемника со ссылками на источники и проверкой обоснованности, база знаний, пробелы, `make eval`, записи экрана с пошаговой инструкцией и автоматическим размытием персональных данных. Панель руководителя и удаление данных — следующий этап ([план](docs/plan.md)).

## Быстрый старт (Docker)

Нужны Docker с Compose v2.24+ и `make`.

```bash
cp .env.example .env     # для демо можно не менять
make up                  # db, backend, worker, frontend
make seed-demo           # вымышленные демо-данные
```

Откройте http://localhost:3000. Демо-учётки (пароль `demo1234`), на странице входа их можно подставить кликом:

| Роль | Email |
|---|---|
| Руководитель | `manager@demo.local` |
| Эксперт | `expert@demo.local` |
| Преемник | `successor@demo.local` |
| Администратор | `admin@demo.local` |

Полезное: `make logs`, `make ps`, `make down`; API и Swagger — http://localhost:8000/docs; проверка здоровья — http://localhost:8000/api/health.

## Разработка без контейнеров приложения

Нужны [uv](https://docs.astral.sh/uv/) и Node.js 22.

```bash
make install          # зависимости backend и frontend
make dev-backend      # PostgreSQL в docker + backend на :8000 с автоперезагрузкой
make dev-worker       # фоновые задачи (в отдельном терминале)
make dev-frontend     # Vite на :3000, /api проксируется на :8000
```

После изменения API — `make gen-api` (типы для фронтенда из OpenAPI).

## Проверки

```bash
make test        # все тесты: backend (юнит + интеграционные на PostgreSQL) и frontend
make test-unit   # быстрые юнит-тесты backend без БД
make lint        # ruff, import-linter, mypy, eslint, prettier, tsc
```

Тесты не требуют GPU, интернета, ключей и скачанных моделей: LLM, ASR и эмбеддинги в них — fake-провайдеры, а реальные провайдеры проверяются на подменённом HTTP.

## Модели: локально через llama.cpp

Без модели (`LLM_PROVIDER=fake`, по умолчанию) приложение работает: интервьюер задаёт заготовленные вопросы, но не понимает ответы и не извлекает карточки. Демо-данные (`make seed-demo`) уже содержат завершённое интервью и карточки.

Чтобы подключить настоящую модель, запустите [llama.cpp](https://github.com/ggml-org/llama.cpp) **на хосте**. В Docker на macOS нет доступа к GPU, поэтому модель в контейнере работала бы слишком медленно (решение D-033).

1. Установите llama.cpp: `brew install llama.cpp` (macOS) или соберите по инструкции проекта (Linux, CUDA).
2. Скачайте GGUF-модели (выбор модели — решение команды, ТЗ п. 17.1). Ориентиры: instruct-модель 7–14B семейства Qwen или T-lite/T-pro в квантовании Q4_K_M/Q5_K_M; для эмбеддингов — GGUF-версия `bge-m3`.
3. Запустите два сервера:
   ```bash
   llama-server -m ./models/llm.gguf --port 8080 -c 16384 --jinja             # генерация
   llama-server -m ./models/bge-m3.gguf --port 8081 --embeddings --pooling cls  # эмбеддинги
   ```
4. В `.env`:
   ```bash
   LLM_PROVIDER=openai_compatible
   EMBEDDINGS_PROVIDER=openai_compatible
   ASR_PROVIDER=faster_whisper
   ```
   Адреса `http://host.docker.internal:8080/v1` и `:8081/v1` уже прописаны в `.env.example`. Если backend запущен без docker (`make dev-backend`), замените их на `http://localhost:…`.
5. `make up` (или перезапустите `make dev-backend`). Проверка: http://localhost:8000/api/health — у `llm` и `embeddings` должно быть `"ok": true`.

Распознавание речи — faster-whisper `small` (D-031). Модель скачивается при первом голосовом ответе (~500 МБ) и хранится в volume `models`. В закрытом контуре укажите в `ASR_MODEL` путь к заранее скачанной папке модели.

Индекс ассистента строится эмбеддингами, заданными в `.env`. После смены модели эмбеддингов (например, с `fake` на bge-m3) пересоберите индекс: на демо-стенде — `make seed-demo`.

`OFFLINE_MODE=true` запрещает обращения к нелокальным адресам: `host.docker.internal`, `localhost` и адреса из частных диапазонов разрешены.

### Модели в контейнерах (профиль `local-llm`)

Если модель должна работать в контейнере (сервер с Linux и GPU, закрытый контур), положите GGUF-файлы в `./models` и запустите:

```bash
make up-local-llm
```

В `.env` укажите `LLM_BASE_URL=http://llm:8080/v1` и `EMBEDDINGS_BASE_URL=http://embeddings:8080/v1` (имена файлов — `LLM_GGUF`, `EMBEDDINGS_GGUF`). Образ по умолчанию работает на CPU; для NVIDIA задайте `LLAMA_CPP_IMAGE=ghcr.io/ggml-org/llama.cpp:server-cuda`. С `OFFLINE_MODE=true` эти адреса разрешены: это имена сервисов compose.

## Ассистент и оценка качества

Преемник задаёт вопрос → гибридный поиск по подтверждённым карточкам (вектор + полнотекст + RRF) → если ничего близкого нет, честный отказ и вопрос уходит эксперту как «пробел» → иначе LLM отвечает со ссылками `[n]`, судья проверяет каждое утверждение, неподтверждённые удаляются. Без модели ассистент показывает найденные карточки без пересказа.

```bash
make eval                 # на модели из .env; отчёт в eval/reports/<дата>_<модель>.md
make eval PROVIDER=fake   # без модели: проверка, что пайплайн не сломан (так же в CI)
```

Отчёт: правильность ответов (LLM-судья), полнота цитирования, корректные и ложные отказы, обоснованность, задержка p50/p95, перебор порогов отказа `RAG_MIN_SIMILARITY` и `RAG_MIN_TEXT_COVERAGE`, список провалов. Набор вопросов — `eval/datasets/demo_qa.jsonl` (57 вопросов, 21 без ответа в базе).

## Записи экрана

Эксперт записывает экран с голосовым комментарием прямо в браузере (или загружает видео до 1 ГБ). Worker извлекает звук (ffmpeg), распознаёт речь, LLM делит запись на шаги, для каждого шага сохраняется кадр. На кадре Tesseract находит текст, а телефоны, email, СНИЛС, ИНН, паспорта, номера карт и ФИО размываются. Получается черновик инструкции со скриншотами; шаги открывают видео с нужной секунды.

- Для демо есть вымышленный портал: http://localhost:3000/mock-portal/ — в нём удобно записывать экран.
- В демо-данных уже есть обработанная запись. Пересоздать её видео и шаги: `node demo/record_demo.mjs` (нужны Playwright и ffmpeg).
- ffmpeg и Tesseract (`rus+eng`) уже в образе backend. Без docker их нужно поставить в систему (`apt install ffmpeg tesseract-ocr tesseract-ocr-rus` или `brew install ffmpeg tesseract tesseract-lang`).
- Для обработки новых записей нужны распознавание речи (`ASR_PROVIDER=faster_whisper`) и LLM.

## Панель руководителя и защита данных

- **Панель** (`/dashboard`, руководитель): карта рисков по процессам подразделения — важность, кто ещё знает процесс, покрытие подтверждёнными карточками, открытые пробелы, срок и уровень риска (формула ТЗ п. 7.9, границы уровней — `RISK_HIGH` и `RISK_MEDIUM`); матрица «процессы × аспекты»; прогресс каждой передачи; метрики за период с выгрузкой в CSV.
- **Мои данные** (`/privacy`, эксперт): согласие и его отзыв, что хранится, удаление отдельной записи экрана или всех своих данных по передаче. Карточки, у которых не осталось источников, уходят в архив и пропадают из ассистента.
- **Срок хранения**: видео и голос старше `RETENTION_DAYS_RAW_MEDIA` дней worker удаляет сам; скриншоты, шаги и карточки остаются.
- **Журнал** (`/audit`, руководитель и админ): вход, просмотр записей, подтверждение карточек, согласия, удаление данных.

Подробно — в [`docs/privacy.md`](docs/privacy.md).
